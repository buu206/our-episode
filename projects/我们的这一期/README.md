`run.sh` 先调用 `setup-local.py` 检查配置，然后通过 `uvicorn --factory app.main:production_app` 启动单进程服务，默认监听8788。已有配置不会被覆盖，也不会打印正常服务的邀请码。终端按 `Ctrl+C` 正常停止；端口占用时先检查已有进程，不要让多个worker同时处理同一目录。

## 朋友供材与采访

在3000或3001正式网页登录，**选择节目 → 制作页下方“这一期，和朋友一起” → “朋友供材与采访”**，进入当前节目的正式协作页。

1. 发起人填写朋友称呼，在“邀请用途”选择“朋友供材”“事后采访”或“片段核对”。采访与核对需指定不超过30秒的原片上下文；问题和表达建议均由人填写，本轮不调用AI。
2. 创建邀请后，点击“在本机打开邀请”可在同一电脑体验双方流程；也可复制本机邀请链接。邀请默认7天有效，持码身份不是实名核验。`localhost`／`127.0.0.1` 链接只指向打开链接的电脑，不能作为外网朋友邀请；应用不会代发。
3. 验证真实权限隔离时，在另一浏览器或独立浏览器配置中打开朋友链接；不同受邀者也使用独立会话。同一浏览器的新标签会共享朋友会话，只适合快速体验。打开另一份邀请时若提示已有朋友会话，先点“退出后使用这份邀请”，再填写称呼、确认身份并进入；页面不会自动换人。朋友仅能看到该任务的必要上下文与本人稿件。
4. 供材上传MP4/MOV；采访上传WAV/MP3/M4A语音或MP4/MOV视频，须保留本人原声。先等待本机预览，完整预听／预看并勾选本人确认，点“确认并提交给发起人”，再在弹窗点“本人确认，提交”。未提交的草稿及放弃的草稿不向发起人公开。采访问题可修改或跳过；核对角色的问题只读，不能上传稿件。未回复或跳过不阻断原有成片。
5. 发起人查看已提交内容，点“采用这段已确认表达”，在弹窗点“确认采用这一修订”，等待采用状态显示“已加入素材”，再回制作页刷新并显式加入新版本，原成片保留。修改文字或截短区间需另建修订，由本人再次确认；确认只绑定该修订，不自动授权后续修改。采访素材持续标明“事后采访”，本人确认的文字说明不是自动转写。
6. 朋友可对授权范围内的内容提出异议或撤回使用授权。相关内容和依赖版本会受限；问题由提出者确认解决，或在新版本移除关联内容。发起人不能代替朋友认可表达，产品也不能收回已下载到外部的副本。

所有原始来源共用**每期8份、总600秒、总1GiB（1,073,741,824字节）**额度，包括发起人上传、朋友供材及采访。普通供材可单条超过60秒或100MB，但仍须满足本期剩余额度；**采访每份另限60秒、100MB（100,000,000字节）**。朋友投稿的草稿、已放弃但留存的文件和撤回授权后留存的文件仍占配额，其原片副本实际删除成功才释放；预览和采用生成的派生副本不重复计为原片。本人明确删除未提交草稿的接口与页面已验证；不能把“放弃／撤回”当作已删除。发起人原片在确认删除并撤权后即不计入额度；若物理清理失败仍会列在待清理区，需重试。额度不是磁盘存储占用统计。

确认修订的文字和区间保持固定，编辑器不能直接改写；需要改变表达时回协作页新建修订。供材仍是现场素材，采访明确为事后补充，二者不会混标。阶段2-2已于2026-11-08获得用户明确本机验收；双方操作步骤见[照着做清单](docs/evidence/阶段2-2/照着做清单.md)，工程依据见[阶段2-2是否表](docs/evidence/阶段2-2/是否表.md)。原技术成片保留在 `data/验收成片/2-2协作技术验收-非人物非AI.mp4`。

2. 在明确的演示提示下分析素材，查看固定测试观察与转写，回看来源并修改或移除内容。

## 数据与恢复

- 正常服务使用 `data/app.sqlite3`、`data/assets/`、`data/outputs/`；演示服务在 `data/demo/` 下独立保存，二者不共用业务数据或邀请码。应用副本保留到主动删除，不改写外部源片。
- 会话、节目、证据修订、选定方向、版本、任务、人工确认与费用账本，以及协作邀请、本人稿件、表达修订、采用、异议、分享授权和独立观看会话均持久化。分享固定版本、revision、期限与关闭状态跨重启保留。页面关闭不等于任务取消；中断后查看失败状态，从成功检查点继续，费用未知的调用先保留占用。
- 更新素材或证据会使旧方向、依赖版本失效，旧文件存在也不允许绕过权限导出。删除先展示影响并确认；物理清理失败返回受控错误，重复删除或重启可继续处理。
- 每个数据目录只运行一个服务进程与一个worker，不使用多worker或reload。未标记的孤立临时文件不自动清扫，以免误删。
- `data/`、`backend/.env` 保持Git忽略。备份前先正常停止对应服务，再复制整个数据目录，避免只复制仍在写入的SQLite主文件。
