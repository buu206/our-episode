**本稿梳理目标用户在真实场景中想完成的事、可能遇到的阻碍和成功表现，供产品设计与后续用户研究共同使用。**当前依据为原始方案与项目发起人的共创选择，尚无终端用户访谈、素材观察或使用测试结果。文中的需求与优先级是待验证的工作假设。

# 文档目标与依据

产品方案确定产品主张与整体体验；本文件解释谁在什么情况下需要什么、为什么需要、如何观察问题是否得到解决。后续功能 PRD 再定义页面、交互状态、具体限制与研发验收。

这次先围绕“聚会之后，在 AI 导演的引导下，和朋友一起做出一期真实、有趣、愿意分享的节目”整理需求。用户要参与选择方向，产品需要帮助其理解选择；自行写脚本和熟练操作剪辑工具不应成为开始制作的前提。

## 已确认的产品选择

| 依据编号 | 本轮确认内容 |
|-|-|
| D1 | 优先面向熟人小圈子的日常聚会，包含做饭、生日和周末相聚。 |
| D2 | 真实素材剪成热闹综艺，再用当事人的真实事后采访补充视角。真实观感是重要取舍。 |
| D3 | 先在熟人之间分享；有机会或大家喜欢时，再由用户决定是否发布到公开平台。 |
| D4 | 采用热闹的综艺导演组风格，花字和互动更多，导演组以画外音存在。 |
| D5 | 采访支持朋友本人语音和补录片段。 |
| D6 | 素材方式兼顾一人掌握主要素材，以及分散在几位朋友手机里的情况。 |
| D7 | AI 导演先给方向，用户在引导下参与选择，逐步完成一期节目。 |

D1～D7 记录项目发起人的产品取舍，不代表已证明目标人群普遍存在相同需要。尤其不能由 D6 推导出素材分布的市场比例，也不能由 D7 推导出所有用户都不会制作节目。

## 仍需取得的需求证据

后续需要了解真实聚会中拍到了什么、素材由谁保管、大家此前怎样分享或剪辑，以及在哪一步遇到困难。还需验证朋友是否愿意补采访、愿意投入多少时间、对吐槽和公开分享有哪些不同看法。

当前不填虚构画像、访谈原话、满意度或转化率。获得研究材料后，应记录日期、场景、参与角色、实际行为和反例，再修订本稿。

# 目标用户与角色关系

目标用户按活动行为与协作角色划分，同一个人可以同时承担多个角色。年龄、职业、收入和使用频率暂不作为已验证画像。

| 角色 | 希望完成的任务 | 需要关注的阻碍 |
|-|-|-|
| 制作发起人 | 收集本次聚会素材，在 AI 引导下决定本期内容，完成修改和分享。 | 不知道素材够不够、不知道怎样选方向、担心制作太费力，或一直等不齐朋友。 |
| 素材贡献者 | 把自己拍到的片段补给同一期节目，同时知道材料将被如何使用。 | 不清楚要交哪些片段、已经交过什么，或不愿让其他人看到整份相册。 |
| 出镜与采访参与者 | 理解自己相关的片段，补充真实视角，并表达对呈现方式的意见。 | 不清楚为什么被问、担心话被剪歪、不想出镜或没有时间回复。 |
| 熟人观众 | 顺利观看、听懂故事、认出熟悉的互动，并保存愿意重看的记录。 | 看不懂前因后果、关键原声被遮盖，或看到的内容令当事人不舒服。 |

表中阻碍是研究假设。第一版不以专业剪辑团队、商业综艺制作方和以涨粉为主要目标的创作者为核心研究对象。公开观看者作为后续场景研究。

# 核心场景与用户任务

以下场景是用于设计和访谈的任务情境，不是已发生的用户案例。

## 聚会结束，一人有主要素材

发起人手机里有这次活动的视频，记得几个有意思的瞬间，但没有明确的节目构思。其任务是知道现有素材能讲什么、挑选一个喜欢的方向，并尽快看到可以判断效果的版本。关注点包括启动负担、选择是否易懂，以及成片是否保留了自己重视的片段。

## 素材分散，需要几位朋友补充

不同朋友拍到了不同视角。发起人需要把素材放到同一期节目里，了解目前收到哪些内容，并决定什么时候开始制作。贡献者需要明确自己交给谁、交哪些内容及用途。核心矛盾是素材完整性与等待成本，不能默认所有人必须同时在线或先上传完才能继续。

## AI 给出方向，用户参与选择

用户不熟悉综艺制作，但能判断哪种说法更符合这群朋友。AI 需要根据实际素材提出可理解的方向，并指出支持该方向的片段，让用户知道选中后大致会讲什么。

例如一组做饭素材，可以分别围绕“主厨临时进修”或“大家最后一起救场”组织内容，但每个选项都需要对应真实发生的行动。用户可以补充背景、换重点或要求重新提议。只有一个方向有依据时，不为了凑选项编出其他故事。

## 看到初版，朋友想补一句

参与者在具体片段旁看到采访邀请，先理解片段和问题，再选择用本人语音或补录片段回答。其任务是补上当时的想法、背景或另一种记忆，并确认自己的意思没有被改变。发起人需要看清补充后节目发生了什么变化，再决定采用。

本文将“补录片段”按采访语境理解为当事人后来录制的采访或补充说明视频。它与朋友补交的原始现场视频分别处理，不把事后重演当作现场记录。

## 先发给朋友，再考虑公开

熟人观看首先关心内容是否有趣、是否像自己，以及是否适合在这个圈子里分享。转向公开平台时，还需要补足圈外观众理解故事所需的背景，并重新检查不适合公开的片段。熟人愿意观看或接受采访，不自动代表其接受公开传播。

# 需求清单与建议优先级

以下需求均待用户研究验证。P0 表示拟优先覆盖的核心任务或信任底线；P1 表示加强协作与持续使用的需求；P2 表示后续扩展。优先级是本稿建议，不代表已评估研发工作量，也不等于每项需求都要新增独立功能。

## 开始制作与选择方向

**U01｜组织同一期的素材｜P0｜依据 D1、D6。**发起人既能用自己已有的视频开始，也能接收朋友补充的相关片段。贡献者能确认提交对象和素材范围。成功表现是用户能判断本期已有材料、缺什么，以及是否继续等待；没有贡献素材的朋友不阻断制作。

**U02｜在引导下作出有意义的选择｜P0｜依据 D7。**面对素材时，发起人需要先知道可选方向及其差别，再决定本期讲什么。成功表现是用户能用自己的话说明所选方向、指出关联素材，并能修正不符合实际的理解；不需要先学会写提示词或节目脚本。

**U03｜形成真实、可理解且有节目感的故事｜P0｜依据 D2、D4。**发起人与观众希望从片段中看懂一件事，同时认出朋友真实的互动。成功表现是观众能复述主要经过、听清关键原声，并指出具体有趣之处；不能只凭花字多、音效多或生成完成就判定满足。

## 修改、补采访与表达边界

**U04｜纠正结果，同时保留自己喜欢的部分｜P0｜依据 D2、D7 及待验证的操作负担假设。**初版出现遗漏、理解错误或包装不合适时，用户能表达“保留这段”“改正这句话”“弱化这里”等意图，看到相应变化，并找回此前认可的版本。成功表现是重要问题得到修正，用户不必为局部修改重新完成整个过程。

**U05｜轻松补充真实的个人视角｜P0｜依据 D2、D5。**朋友需要理解采访缘由和上下文，自主选择语音或补录视频，也能跳过。成功表现是其可以完成有明确归属的回答，补充内容被正确理解并用于节目。语音与视频各自的参与意愿、负担和效果，需要分别观察。

**U06｜知道自己怎样被呈现，并能提出调整｜P0｜依据 D2、D3 及待验证的参与者顾虑。**出镜者和采访提供者需要核对与自己相关的内容，知道语境是否改变，能拒绝使用某段补充或提出修改。成功表现是用户能说明何处不准确或不合适，并在分享前得到明确处理。具体确认流程待设计，不预设所有人逐一审批整期节目。

**U07｜自主安排协作节奏｜P0｜依据 D6、D7 及待验证的等待负担。**发起人需要决定等谁、跳过谁和何时出片，参与者可以稍后回答或不回答。成功表现是素材或采访未齐时仍能继续；后来收到内容时，发起人可以判断是否值得更新。朋友未回复采访与已提出内容异议分别处理，已有异议的片段需先解决或移除，不能以赶着出片为由直接使用。

## 观看、分享与持续使用

**U08｜顺利分享，并理解可见范围｜P0｜依据 D3。**发起人需要把节目交给熟人，观众需要顺利播放；各方应能理解原始素材、采访和成片分别对谁可见。成功表现是接收者能够观看，发起人能说明分享范围，并能停止产品内链接的后续访问。已下载或已转发至外部的副本，不承诺由产品统一撤回。

**U09｜处理中断后继续完成｜P0｜依据待验证的等待与重复劳动问题。**上传、生成或修改耗时较长时，用户需要知道进展、是否要操作，以及哪些内容已保存。成功表现是用户能判断继续等待还是重试，中断后不必无理由地重传已成功接收的素材或重做已确认的选择。

**U10｜找回以往作品并重看｜P1｜依据待验证的保存与重看任务。**活动过去一段时间后，发起人与朋友需要找回已经分享或保存的成片。成功表现是用户能够找到对应活动并重新观看。当前制作中的版本确认与回退由 U04 覆盖；完整连续剧、长期人设与共同梗记忆不在本条自动扩展。

**U11｜为公开观众调整内容｜P2｜依据 D3。**用户决定公开时，需要补背景、处理圈内梗及重新确认表达边界。成功表现是用户能识别需修改之处，并自行完成公开发布选择。公开流量和涨粉不作为第一版的成功标准。

**U12｜下一次活动更容易获得可用素材｜P2｜依据此前保留的拍摄辅助方向。**用户再次活动时，可能需要知道哪些镜头有助于讲清故事。成功表现是提示带来有用素材，且参与者未因配合拍摄而明显减少活动乐趣。具体需求强度与是否启用，应单独验证。

# 关键取舍与边界情况

| 相互牵制的需要 | 本稿建议的处理原则 |
|-|-|
| 引导充分与操作省事 | AI 先提供有依据、易理解的方向；只在影响故事或表达的地方引导选择。用户可以接受建议，选项数量和选择轮次通过原型观察确定。 |
| 素材齐全与及时出片 | 让发起人了解已收到什么，再决定继续、等待或补充。未齐不等于失败，也不自动认为现有素材能支撑完整故事。 |
| 节目热闹与真人真实 | 画外音、花字和回放围绕已发生的事情展开。保留关键原声，不拼接不相关的反应来制造虚假因果。 |
| 发起人完成作品与当事人表达意见 | 发起人组织制作；当事人有可理解的内容核对与修改途径。意见冲突时优先提供删减、替换和仅保留合适版本等选择。 |
| 参与便利与分享可控 | 朋友只为明确的一期补素材或采访，并了解用途。邀请回复、查看原片和观看成片的权限分别设计。 |

素材少、原声嘈杂、人物称呼不明或没有适合的笑点时，需要让用户知道缺口及可选动作。可以补背景、校正字幕、换主题或制作较短回顾。效果不佳的作品也要纳入验证，不能只研究成功样片。

画外音的声线、节目时长、横竖屏、产品载体、保存期限和收费方案仍属于后续设计取舍。当前不把“用户需要某个平台、某个时长或某种会员”写成已经成立的需求。

# 用户研究与需求验证计划

先开展小规模定性研究，目的是找出需求是否存在、在哪些场景成立以及有哪些反例。招募应覆盖主要拍摄者、分散持有素材的朋友、不愿补录或不喜欢被吐槽的参与者，并包含拍过却没有剪成的人。具体人数与安排另定，小样本比例不直接外推到市场。

## 先看真实经历，再讨论产品

1. 请参与者回顾最近一次具体聚会，说明拍了什么、素材在谁手里、后来如何处理。经其同意查看其愿意展示的材料，不要求开放整个相册。
2. 追问此前是否尝试过剪辑或分享，在哪一步继续或放弃，实际用了什么办法和多少时间。
3. 了解什么内容适合发群、什么不愿公开，以及是否曾因剪辑或玩笑表达产生顾虑。
4. 再展示概念或样片，观察参与者的选择和行为，避免先介绍产品后只问“你愿不愿意用”。

## 按关键假设安排测试

| 关联需求 | 要验证的假设 | 验证方法与需要记录的反例 |
|-|-|-|
| U01、U07 | 一人素材与多人补充都能顺利开始。 | 分别观察两种素材任务，记录汇集成本、遗漏和等待。有多少材料最终被用到，以及哪些人不愿贡献，不只记录收到多少条视频。 |
| U02 | AI 给方向能帮助用户作出选择。 | 给同一素材的真实可行方向，让用户解释差别并选择。记录不理解、选项与素材不符、要求重提和选择耗时；另观察少量选择是否仍显繁琐。 |
| U03、U06 | 综艺版本既有趣，也能被当事人接受。 | 用相同素材比较普通回顾和综艺版本，交替展示顺序。分别收集发起人、出镜者和熟人观众意见，分开记录好笑、真实和愿意分享。 |
| U04、U09 | 用户能以可接受的投入修正并完成。 | 记录从素材准备到认可成片的主动操作时间、系统等待、纠错次数及放弃原因。观察一次中断或修改后能否找回成果。 |
| U05、U07 | 真实采访的增益足以支撑参与成本。 | 在同一综艺初版上比较加入采访前后，分别观察语音与补录视频的实际参与。记录跳过原因、内容是否采用以及哪些采访没有改善效果。 |
| U08、U10 | 节目会被实际分享、保存或再次使用。 | 经参与者同意观察实际分享或后续反馈，并记录没发的原因。之后有新的合适活动素材时，再询问是否复用；不把“下周没聚会”当作拒绝产品。 |

使用固定问题比较同素材版本，并记录观看顺序、人工参与程度与修改投入。手工制作的样片只能证明体验可能成立；自动完成质量、速度和成本需要另行验证。

# 观察指标与统计口径

下列指标是采集口径建议，目标值待试验基线建立后再定。定性访谈保留原始人数与具体原因，不将少量样本包装为稳定比例。

| 观察项 | 建议口径 |
|-|-|
| 方向选择是否有效 | 记录能否解释选项并完成选择、是否要求重提，以及后续是否推翻所选方向。未选择者计入该阶段流失。 |
| 制作完成 | 以已经提交素材并开始制作的项目为分母，记录其中形成用户认可、可分享版本的项目数；同时列出素材不合适、等待和生成失败的原因。 |
| 用户投入与系统等待 | 分开记录汇集素材、选择、纠错和采访的主动投入，以及上传与生成的等待。多人项目记录各角色投入，避免只算发起人时间。 |
| 采访参与与采用 | 对明确收到邀请的朋友，分别记录实际回应、跳过、未回应；对已提交采访，记录被采用情况。按语音和补录视频分别观察，不推测无法确认的邀请到达。 |
| 真实表达问题 | 记录人物、原话、因果、反应和采访归属的错误，以及是否解决。不能用有趣程度抵消当事人的失真异议。 |
| 实际分享 | 以已经产生可预览作品的项目为观察范围，分别记录导出、产品内分享和经用户确认的实际发群。导出不直接等于已分享。 |
| 再次使用 | 观察期和后续访谈安排在研究启动前确定；在已确认有下一次适合素材的用户中记录实际复用。没有新素材和有素材但没使用分别列出。 |

# 开放问题与文档维护

本轮已确定素材兼顾集中与分散两种情况，并采用 AI 导演引导选择。以下问题需要下一步通过原型、真实材料或单独讨论补足，当前不妨碍使用本稿开展需求研究。

- 自然拍摄的素材中，哪些活动最容易支撑一期节目，哪些常常只有照片、缺原声或缺结果。
- 用户需要多少引导才能理解并选择方向；哪些决定值得先问，哪些可以先给默认结果。
- 朋友通过什么入口交素材和采访最方便，以及是否愿意注册或安装独立应用。
- 怎样在少打扰参与者的同时，让其核对有关自己的表达并处理异议。
- 不同素材规模下，主动操作时间、系统等待和处理成本分别是多少。
- 保存期限、删除范围和付费方式，是否与真实使用频率和用户预期相符。

每条需求沿用 U01～U12 编号。研究后追加证据来源、日期、支持与反对材料，以及保留、调整或暂缓的结论，再同步到产品方案。后续细化功能 PRD 时沿用需求编号和证据状态，让具体行为与验收可追溯到用户任务。
