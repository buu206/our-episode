# 阶段3-1技术开发文档｜正式核心制作网页

日期：2026-11-08。核心代码与本机联调已实现；最终工程结论以证据包原始自检为准，用户验收、手机真机与真实AI分别记录。

## 1. 目标与范围

用户在正式电脑/手机网页完成“素材→核对与方向→编辑→预览确认”，得到经本人确认的MP4；刷新可找回已保存版本和任务。风格按用户选择：更活泼、节目感更强的生活综艺导演台。

包含登录、最近制作、创建一期、上传/原片播放、来源核对、方向、选段/花字/包装/旁白、新版本、任务与失败恢复、确认导出、删除影响与清理恢复。新增同源流式代理以及前端必需的后端兼容字段。3-2的正式协作、采访、分享页面不在本轮，仍提供明确标记的临时入口；原功能和数据保留。

## 2. 实现与状态

- 路由：`/login`、`/`、`/episodes/[id]?step=materials|direction|edit|preview&version=id`；API为同源`/api/v1/*`。
- 维护源：`frontend/src/app`路由，`components`业务与UI，`lib`集中类型/API/代理；`backend`仅兼容补齐，不改变既有字段含义。
- Next/React/TypeScript strict/Tailwind/Lucide；精确安装版本记录于package.json及package-lock.json，Node24.22.0。无外部字体、监控、模型直连或浏览器持久凭据。
- 后端为唯一业务事实来源。URL恢复已保存工作；脏表单由页面保留并提示离开影响，不伪造自动保存。
- 浏览器支持可取消的Navigation API返回事件时，在跳转前确认是否放弃修改；不可取消或不支持该能力时，节目编辑和证据草案保留在当前标签内存，重新进入时提示恢复，保留原base_version_id和证据revision。不会保存到localStorage或冒充已提交，刷新、换号或退出会清除；明确放弃或成功保存也会清除对应草案。
- 普通HTTP/有节制轮询；任务终态停止，后台页停止查询，连续错误按2/4/8/16/30秒退避，成功或回到前台重置，并丢弃过期响应。没有SSE、真实任务百分比、取消任务或上传断点续传，不显示相应能力。

## 3. API契约与安全

完整契约沿用前端适配声明第3–5节及后端OpenAPI。登录Cookie/CSRF与错误`{error:{code,message}}`保持；api.ts集中请求、校验和错误归一化，媒体保留后端授权。

新增EpisodeOut.quota为整期实际用量与限额，包含私密稿件占用但不返回稿件内容；pending_cleanup只列owner本期已撤权仍待物理清理的asset_id/filename。证据PUT上限2MiB，其余JSON仍64KiB；schema字段限制不放宽。

流式代理固定运行时loopback后端地址，精确检查外部前端Host/Origin后转发（Next内部重建的Request.url origin不作为浏览器Host依据），保留Cookie/CSRF、多个Set-Cookie、Range/HEAD、响应状态和no-store；禁止路径穿越/外部重定向，移除逐跳头，不缓冲整个视频，客户端断开取消上游。数据源不能由浏览器切换。

证据核对、旁白确认、成片确认独立；新修改保存为新版本。含本人确认采访的fixed_segment不能绕过修订确认再截短或加字幕。受限版本不显示可播放源；删除前展示关联分享。模型/渲染失败分别按原接口恢复，费用未知不清除占用。非幂等POST超时先核查，不自动重放。

- 新装Lint依赖带入的minimatch受影响版本，按[上游安全公告](https://github.com/advisories/GHSA-g3hv-75wg-m249)精确覆盖为11.0.1；仅作用于typescript-estree使用的minimatch函数，保留其它旧API使用者的依赖，不盲目降级Next。安装后审计0漏洞，最终Lint/类型/构建通过。
- 后端素材media、版本media和export显式兼容GET/HEAD，授权、来源限制、确认状态和Range保持同一实现。导出先HEAD检查权限与文件，再用浏览器原生下载，不把整部影片读进前端内存。HEAD通过与实际下载之间的变化仍由后端检查；“交给浏览器”不等于宣称磁盘下载已成功。
- Next生产构建采用standalone；npm start使用scripts/start.mjs复制必要静态资源并绑定127.0.0.1。正常/演示启动脚本显式设置BACKEND_MODE与固定APP_ORIGIN。
- 本机Turbopack在重新编译CSS时创建临时端口被运行环境拒绝，生产命令采用官方支持的`next build --webpack`。框架、依赖与全部检查保持，构建方式依据[Next官方安装文档](https://nextjs.org/docs/app/getting-started/installation)及本机CLI帮助；最终页面及13,921,562字节传输已在此构建上复核通过。
- 首次浏览器调试发现扩展在body注入mpa-*属性触发React hydration警告，已经定位至浏览器扩展；不为隐藏警告添加suppressHydrationWarning。应用功能错误与预期请求拒绝分别记录。

- 实际Next16.4.5出口会统一省略Content-Length，并以chunked传GET媒体；HEAD无body且可不带长度头。这符合[RFC9110 §8.6](https://www.rfc-editor.org/rfc/rfc9110.html#section-8.6)。验收检查状态/权限/Content-Range、完整GET字节与SHA；长度头若存在必须正确，不把可选头缺失当作影片截断。
- 实际集成发现Next为空DELETE构造可读流，已兼容读取到EOF的无类型空请求；非空无类型仍415，上传格式和CSRF/来源/字节限额保持不变。
