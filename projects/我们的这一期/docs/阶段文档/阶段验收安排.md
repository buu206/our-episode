# 阶段验收安排

更新日期：2026-11-08。仅适用于“我们的这一期”，不改变其他产品的默认验收流程。

用户已明确：先完成本机工程与流程验收，上线前再接入阿里云；不使用本地模型、不提交工单。阶段2-1、2-2、2-3均已获得用户本机验收通过，按既定路线进入前端适配。此安排允许相邻本机阶段继续，不把真实AI待验改写成通过。

## 两种验收分别记录

- **本机验收**：验证业务流程、权限、人工确认、素材处理、版本、预算守卫和恢复。`verify.sh` 的第2、4、5、6、10项必须通过或不适用，唯一未通过项只能是第3项真实模型冒烟待验。用户需亲自确认当前阶段本机体验。
- **真实验收**：模型准入条件满足后，执行真实调用、核实转写时间戳与视听理解、使用5–10条真实样例打分并确认内容效果。调用成功不等于内容验收通过。必须保留逐阶段自动冒烟记录、完整自检结果和用户实际反馈。

本机验收后，是否表第3项仍写“待验”，原始 `verify-输出.txt` 仍保留未通过结论。管家记录“本机验收通过（真实AI待验）”，并累计待验阶段；不能声称完整阶段通过。正常8788服务默认禁云；8790独立演示使用固定测试结果与合成提示音，醒目标明“非真实AI／非真实旁白”，不计入真实验证。

## 管家操作

1. 用户明确通过本机验收后，维护下方该阶段的确认与反馈记录，再运行 `bash kit.sh 本机通过 我们的这一期 <下一本机阶段>`。命令现场重跑原 `verify.sh`，核对本次输出与证据文件；工程失败、未配置、缺项、重复项或记录不一致均拒绝推进。
2. 仅允许按现有路线进入相邻的阶段2或阶段3；无代码阶段3-0继续走原验收流程。待验阶段累计保存在管家状态与历史中，不覆盖过去记录。普通“通过”、窗口路线和手动校正均不能带着待验记录进入阶段4、阶段5或“完成”。
3. 上线或收尾前，逐阶段完成真实验证与用户反馈，在下方新增对应 `kit-real-ai-accepted` 和 `kit-real-ai-feedback` 记录，再运行 `bash kit.sh 真实验收 我们的这一期`。管家逐阶段重跑原自检，要求五项工程通过/N/A且真实模型有有效记录；全部通过才清除待验列表，并追加清账历史。任一失败保留全部待验记录；此命令不自动推进阶段。
4. 无论是否采用本机先行，完整自检六项通过后仍可走原来的“通过”流程。真实模型准入、隐私、人工确认及3元/任务、30元/首批预算限制不变，不借此开户、充值、索要Key或外发素材。
