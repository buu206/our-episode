## 1. 阶段目标与范围

打通“发起人确认具体版本和观看范围→建立受限分享→观看者换取独立会话→观看固定版本→主动关闭／到期／内容受限→拒绝后续访问→发起人明确更新安全版本”的本机链路。供材、采访、原片访问与成片观看分别授权，既有版本与人工确认不被分享动作改写。

| 需求与验收项 | 本阶段约束 |
| --- | --- |
| FR11；AC28–30 | 固定已确认版本；观看身份只获得该分享；关闭及过期后旧页面与旧媒体地址的新请求均拒绝；生成新版不静默替换 |
| FR08、FR10；AC21–22、27 | 未解决异议、撤回、删除及确认失效阻止继续分享和取媒体；不承诺收回已下载、转发或缓存到设备的数据 |
| FR12–13；AC32–33 | 分享、版本及派生来源可追溯；旧版保留不覆盖当前授权；恢复和回退不能绕过限制 |

本轮不实现公开推荐流、自动发布、外网部署、付费权限、DRM或正式手机网页。127.0.0.1仍只供同一电脑验收，不能把本机链接当成朋友在其他设备可访问的线上服务。

## 2. 本机分享默认规则

以下是本轮已明确采用、可回退的本机默认，不把PRD原先未定的规则冒充为用户已逐项确认的线上政策；上线前核实实际使用方式。

| 项目 | 本轮规则 |
| --- | --- |
| 观看授权 | 每条分享独立填写称呼，创建强随机观看码。观看码只授予这一条分享，经同源登录换取独立HttpOnly观看会话；持码身份不等于实名核验 |
| 分享对象 | 发起人显式选择自己有权管理且当前已确认的内容版本，并核对其依赖与可见范围 |
| 有效期 | 创建时可选1、3或7天，默认7天；期限从创建时计算。到期不自动续期 |
| 下载与转发 | 只提供受控观看，不新增观看者独立下载接口；仍不能阻止浏览器保存、录屏、转发链接或访问码。应明确说明持码人可能获得观看权限 |
| 主动关闭 | 立即拒绝后续访问和媒体获取；关闭不可恢复，需要重新创建分享 |
| 到期 | 拒绝后续访问和媒体获取；到期不可恢复，需要重新创建分享 |
| 内容受限 | 异议、撤回、删除或确认失效使受影响分享停止观看。问题解决不自动恢复；发起人须显式更新至重新确认且当前安全的版本 |
| 更新分享 | 只适用于未关闭且未到期的分享。可选择另一安全版，或重新确认安全后仍选同版；都必须显式操作，revision递增，不延长原到期时间 |
| 新版与旧链接 | 新版生成、采访迟到、异议解决或旧版重新确认本身均不改分享目标。旧媒体地址不能绕过当前分享revision和授权检查 |

关闭分享、撤回使用授权、删除文件是不同动作。关闭和到期不自动删除素材与成片，继续遵守本机保留到主动删除的规则；物理清理与配额释放沿用已有删除机制。

## 3. 技术适配与权限边界

沿用Python3.12、FastAPI/Pydantic、SQLAlchemy/Alembic、SQLite、本地媒体目录与单进程worker。新增分享和观看会话持久实体，用增量迁移保留既有数据；不新增云服务或模型依赖。

正常入口 `scripts/run.sh` 继续绑定127.0.0.1:8788；独立演示入口 `scripts/run-demo.sh` 绑定127.0.0.1:8790，数据使用 `data/demo/`。演示的固定观察与提示音仍明确标为非真实AI、非真实旁白，分享成功不改变其性质。

- owner仅管理自己节目下的分享；查看、创建、关闭、更新都在后端核对归属，写操作还须验证来源和CSRF。
- viewer会话与owner、participant会话使用独立Cookie，不因共处浏览器而互相授予权限。viewer不得读取节目列表、原片、他人采访、owner导出接口或其他分享。
- 所有媒体请求，包括Range请求，都重新核对分享状态、期限、当前revision、固定版本确认及来源依赖。资源ID、旧URL、已有会话或磁盘文件存在都不能代替授权。
- 原始观看码只在创建时返回，数据库保存摘要；会话凭据不进入URL、日志或前端持久存储。链接如使用URL片段带入代码，仅作启动传码，读取后立即清除，再由同源POST请求体兑换Cookie；片段不随初始HTTP请求发送。
- 响应按受限媒体处理缓存，禁止公共缓存复用。媒体最终响应由中间件设置`Cache-Control: no-store`，另有`Pragma: no-cache`及`Expires: 0`，以inline方式播放；媒体URL携带revision并逐次校验。关闭后拒绝的是新的请求，不声称能清除设备已加载内容。

## 4. 状态、版本与派生限制

分享将发起人、节目、固定版本、称呼、观看码摘要、创建与到期时间、关闭状态、内容受限状态及revision持久保存。观看会话绑定唯一分享，保存凭据摘要、有效期和CSRF所需状态。展示状态须区分可观看、主动关闭、已过期与内容受限，不能统一显示“链接失效”而丢失修复方向。

确定性状态转换要求：

1. 创建时检查版本已确认、媒体就绪、来源和采访修订仍可用。未通过时不创建可观看入口。
2. 发起人创建或更新分享属于人工动作，模型不能自主决定对象、可见范围或延长有效期。
3. 原素材删除、采访撤回或未解决异议使依赖版本及分享受限；关联限制须持久保存，进程重启不能使链接恢复可用。
4. 异议解决或依赖恢复不自动重开分享。发起人重新预览并确认安全版本后，才可显式更新分享，revision递增，原到期时间保持。
5. 主动关闭与自然到期优先于内容恢复：不能通过更新版本、重复创建请求、旧Cookie或重启恢复原链接。
6. 新版本生成失败不覆盖旧版；安全的无关分享可继续观看。回到旧版仍检查当前来源和授权，不能恢复被撤回内容。

关闭、更新、依赖限制和媒体读取的并发行为须按当前数据库状态处理，避免检查后继续发布旧授权内容。重复关闭应保持已关闭；更新需能识别已过时的revision，避免多页面静默覆盖。

## 5. 模块与API契约

分享模型、schema、服务与接口分别位于`app/sharing_models.py`、`app/sharing_schemas.py`、`app/services/sharing.py`及`app/sharing_api.py`；迁移004新增Share、ViewerSession与ShareOperation持久实体。既有版本确认、素材删除、采访撤回及异议路径接入分享限制检查；临时owner与viewer页面使用`static/sharing.html`／`sharing.js`和`static/watch.html`／`watch.js`。`scripts/restart-check.sh`扩展原真实进程恢复检查，不操作正常或演示数据。

统一前缀仍为 `/api/v1`，错误沿用 `{"error":{"code":"…","message":"…"}}`，不输出堆栈、凭据或物理路径。owner写请求要求既有CSRF，viewer写请求使用独立观看会话CSRF。

以下为本轮已实现的接口合同；最终检查结果以证据表为准。路径均位于 `/api/v1` 下：

| 方法与路径 | 请求及响应要求 |
| --- | --- |
| POST `/versions/{version_id}/shares` | `{label,expires_days:1\|3\|7,confirmed:true,client_request_id}`；编号必须UUID。返回ShareCreated，首次包含一次性share_code、watch_url；相同请求重放不新增分享，两个秘密字段返回null |
| GET `/episodes/{id}/shares` | `{items:[ShareOut]}`，返回固定版本、revision、期限和关闭／受限状态，不返回观看明码 |
| POST `/shares/{id}/close` | `{expected_revision,confirmed:true}`；返回ShareOut，相同expected_revision的关闭请求重放幂等，关闭后不能恢复 |
| POST `/shares/{id}/update` | `{version_id,expected_revision,confirmed:true,client_request_id}`；仅active/restricted且未过期时可选择同节目已确认安全版；同版也revision++，保持expires_at；相同UUID重放不重复递增 |
| POST `/viewer/auth/login` | `{share_id,share_code}`；返回`{share_id,label,csrf_token}`并建立独立HttpOnly Cookie |
| GET `/viewer/auth/me` | 使用原会话恢复上述身份，不能以重新登录替代恢复验证；同时检查分享状态 |
| POST `/viewer/auth/logout` | 使用viewer的CSRF退出观看会话，不退出owner或participant |
| GET `/viewer/shares/{id}` | 返回`{id,label,title,version_id,revision,expires_at,confirmed_at,media_url}`，只包含此分享的必要内容 |
| GET／HEAD `/viewer/shares/{id}/media?revision=N` | 固定版本与当前revision匹配后返回可播放媒体，GET支持Range；每次请求重新验证全部限制，无独立下载接口 |

ShareOut包含id、episode_id、version_id、label、title、state、revision、created_at、updated_at、expires_at、closed_at、restricted_reason、confirmed_at、watch_path。expires_at与closed_at使用Unix秒，closed_at可空；created_at、updated_at与confirmed_at沿用既有ISO时间字符串，不能统一乘1000处理。restricted_reason为`{code,message}`或null；watch_path不含观看码，只有首次创建的watch_url带启动传码。

viewer Cookie名为当前owner Cookie名追加`_viewer`，正常和演示服务继续分离。有效viewer会话请求 `/auth/me`、分享读取及媒体时，对closed/expired返回410，对restricted返回409；失效会话返回401。GET错误保持统一JSON结构，HEAD仅返回对应状态和头。原角色、归属、CSRF与参数错误沿用401／403／404／409／422的受控约定。并发更新使用expected_revision拒绝过时操作，关闭和更新的幂等只复用已确认的同一操作，不复活终态分享。

## 6. 临时验收界面

发起人从本期工作台选取已确认版本，进入分享管理，填写称呼与有效期，核对“只观看但不能防止保存或转发”的提示后创建。只在本次创建展示观看码／带码入口，用户自行决定分发；本轮不代发消息。

本轮独立技术样片的发起人入口为[8790分享管理](http://127.0.0.1:8790/sharing?episode=91e2de21e9d54c87882a4b92e2319531)，先在8790工作台使用公开测试码`demo`登录。该地址不含观看凭据，观看者仍须使用单独创建的受限入口；原2-1和2-2验收数据保留。

观看者在独立浏览器会话进入受限观看页，只看到指定版本及必要状态。发起人生成新版后，观看页仍显示原版本；只有显式更新才能切换，页面说明更新结果和剩余期限。关闭、到期或内容受限时停止新的媒体获取，给出准确状态，不冒称删除了外部副本。

同一电脑新标签可用于快速体验；权限隔离验收使用独立浏览器会话。同一浏览器不同观看入口若共用同类Cookie，应显示当前会话归属变化，不能把另一个人的分享当作当前任务。临时页面阶段3整体替换，是否表第4、7项按已定临时界面规则处理，不视为正式前端交付。

## 7. 测试与真实进程恢复

本阶段至少验证：

- 创建时未确认版本、错误归属、已受限来源或未就绪媒体被拒绝；只接受1/3/7天。
- owner／participant／viewer隔离、跨分享ID及媒体越权、无效观看码、CSRF与来源检查。
- 新版生成不改变原分享；显式更新递增revision、不延长到期时间，旧revision媒体请求被拒绝。
- 主动关闭和到期后原Cookie、原页面、原媒体URL及Range请求都不能取得内容，也不能更新或恢复。
- 删除、撤回和异议使依赖分享停止使用；问题解决后仍不自动恢复，明确更新至重新确认安全版才恢复；同版恢复也递增revision。
- 原片和采访权限不因观看授权放开；不新增viewer下载接口，不声称播放媒体无法保存。
- 状态及错误文案、缓存头、日志与响应中凭据排除；重复操作及更新并发不绕过限制。

真实重启检查保留 `start/write/read/stop` 合同，由根目录 `verify.sh` 负责强杀、重启和标记比对。脚本在独立临时目录中通过真实HTTP创建节目、短测试媒体及已确认版本，创建可观看与已关闭两条分享，取得并私密保存两份原viewer Cookie。重启后不重新登录viewer，核对原会话、分享固定版本、revision、expires_at和关闭状态；可观看分享能读取对应媒体，已关闭分享的旧会话及旧媒体请求仍被拒绝。同时保留既有节目标记、协作邀请和原participant会话的恢复检查。

所有测试凭据仅放在 `RESTART_CHECK_DIR` 的0600文件，不进入标准输出、日志或证据截图；只输出verify要求的PID、记录ID和随机标记。临时服务禁云且不读取正常 `.env`，验证后由verify清理，不关闭或写入8788／8790已有实例。

2026-11-08局部验证：重启脚本的shell与嵌入Python语法检查通过；已用独立临时实例实际完成短视频上传、FFmpeg渲染、版本确认、分享同版明确更新及关闭，再以SIGKILL结束该测试进程并启动新进程。重启后原viewer Cookie／CSRF、固定版本、revision、expires_at与关闭状态保持；关闭分享的原会话及GET／HEAD媒体请求继续返回410，原participant会话检查也通过。0600凭据文件及日志不含会话／CSRF值的检查通过，临时实例与数据已清理。本记录只对应这次局部验证，不代替本轮完整`verify.sh`输出、浏览器验收或用户验收。

## 8. 本机验收覆盖项（用户已确认本阶段通过）

用户2026-11-08回复“验收通过继续”，详见[用户验收记录](../evidence/阶段2-3/用户验收记录.md)。下列为覆盖项，逐项工程/浏览器证据见是否表，不将总体确认写成用户亲手执行每个自动化边界。

- 浏览器能分清关闭、过期、内容受限，明确说明不能收回外部已保存副本。
- 强杀并重启临时服务后，原viewer会话、固定版本、revision、期限与关闭状态保持，既有owner／participant恢复检查继续通过。
