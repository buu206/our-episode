### 3.2 同源代理与大文件

浏览器统一请求同源`/api/v1/*`，媒体与导出也走同一入口。现有后端只接受本机Host，写请求Origin必须与后端地址匹配，且要求角色自己的CSRF；不能直接跨端口fetch或放开通配CORS。

已采用Next的Node Route Handler集中流式转发`/api/v1/[...path]`，API路径不经过`proxy.ts`。这是对手册默认代理位置的明确偏离：官方说明Proxy会克隆并在内存缓冲请求体，默认仅缓冲10MB，超过后可能仅剩部分内容。本产品单期上传上限1GiB，不能把扩大内存缓冲当大文件方案。依据：[Next请求体缓冲说明](https://nextjs.org/docs/app/api-reference/config/next-config-js/proxyClientMaxBodySize)、[官方BFF与Route Handler说明](https://nextjs.org/docs/app/guides/backend-for-frontend)。上一版已做真实传输检查，记录见[阶段3-1传输验收记录](阶段3-1传输验收记录.md)；该样例不代表1GiB负载或本次改版已验收。

代理实现要求：

- 目标只来自服务端固定`BACKEND_URL`，限受支持的本机目标；客户端不能指定上游、协议或任意路径，拒绝路径穿越和开放代理行为。
- 写请求先按配置的前端精确来源验证Host/Origin及浏览器跨站信息，再将受信任请求的Origin转成固定后端来源；透传原角色Cookie与CSRF。不能先改Origin再验证，也不能信任客户端伪造的转发头。
- 后端仍绑定loopback、保留现有CSRF/归属检查；不为前端联调削弱已验收后端。当前不增加线上代理密钥或信任公网IP头，线上边界留阶段4实测。
- 请求/响应使用流，不把视频整体读入`formData`、`arrayBuffer`、React状态或代理日志；保留multipart边界、状态码、多个Set-Cookie、Content-Type/Disposition、Range/Content-Range、HEAD及no-store。
- 上游缺失返回503统一错误；普通请求、上传和媒体流分别设置超时，不能用短JSON超时截断正常播放。客户端断开时取消上游；移除hop-by-hop头，显式no-store；拒绝离开固定后端的上游重定向。网络失败不自动重放任何有副作用的请求。
- 正常/演示采用独立前端实例和固定后端配置，不能由浏览器切换目标。Cookie身份隔离与后端实例一致。
- 3-1先验证同源登录→真实文件上传→Range预览→确认导出，覆盖超过10MB文件及既定限额边界、流式内存、断开/超时、跨站和Cookie隔离；代理未通过就不铺开其余页面。

### 3.3 3-1已补齐的兼容契约

证据PUT已单独采用2MiB请求体上限，保留最多100项、每项2000字符的schema限制；其他非上传JSON仍为65,536字节。前端提交前检查UTF-8编码后体积并保留超限输入，不放宽字段校验。

剩余额度不能用当前可见素材列表相减：朋友未提交、已撤回但未删除文件也占整期额度。EpisodeOut已新增`quota`聚合，包括`original_count/total_seconds/total_bytes/max_count/max_seconds/max_bytes`，复用后端计量，不泄露私密稿件内容。限额为8份、600秒、1,073,741,824字节，服务端仍作最终判断。

`DELETION_PENDING`表示访问已停止但物理清理未完成。EpisodeOut已新增受归属保护的`pending_cleanup:[{asset_id,filename}]`，依据后端持久删除标记和待清理引用，刷新后恢复重试入口。不能因素材从列表消失就显示“文件已删除”。这些增量不改变已有字段含义。

## 4. 状态、人工确认与恢复

`/status`中`cloud_enabled`、`workflow_enabled`、`model_mode`分别处理：正常云关闭仍能手动剪接；演示云关闭但流程可用，持续显示“固定结果，非真实AI；提示音非人声旁白”。不能用工程字段`stage`控制用户步骤。

| 状态 | 页面行为／事实来源 |
| --- | --- |
| idle | 尚未选素材或未发起任务，显示条件与下一步 |
| submitting | 当前提交禁重复；上传只显示实际已传输进度，传完后另显示“校验素材”，不代表服务端已保存 |
| queued | Job已持久受理，显示“等待处理” |
| running | 显示Job.stage；不造百分比或预计时间 |
| streaming | N/A：当前无流式任务事件 |
| waiting_user | 证据待核对、方向待选择、旁白待确认或成片待确认；分别显示影响与动作 |
| succeeded | 该Job结束；不等于成片已获人工确认或AI内容正确 |
| partially_succeeded | 多文件上传等批量操作按各文件真实结果汇总；成功项目保留，失败项可单独处理，不新增虚假的Job枚举 |
| failed | 显示业务错误及恢复动作；保留已有版本与页面输入 |
| cancelled | N/A：没有后端取消能力；只允许“离开页面/停止等待”，不声称任务停止 |
| disconnected | 请求中断不等于任务失败；按原ID回查，不重建任务 |
| stale | revision过期或来源变更；保留本地输入，要求重新核对，不静默覆盖 |
| loading | 请求尚未完成，不闪现“暂无素材/作品” |
| empty | 仅请求成功且确实无结果时展示添加素材或手动剪接入口 |
| permission_denied | 401重新登录；403解释范围并返回有权入口，不泄露其他用户内容 |
| not_found | 对象不存在或不可见；返回节目列表，不暴露存在性 |

版本状态映射保留`draft/voicing/rendering/ready/confirmed/failed/restricted`。`ready`可预览、不能导出；`confirmed`仍须服务端重新验证来源；受限时隐藏媒体源并说明处理路径，历史文件存在不代表可使用。

三个确认点不能合并：①保存并确认证据；②确认具体旁白文字与音色使用；③完整预览后确认这一个成片版本。分享及采访确认继续独立，留3-2正式页面承接。修改选段/花字/包装/旁白保存为新版本，不覆盖旧版。

活动任务成功查询后间隔2秒；连续查询错误按2/4/8/16/30秒退避并封顶30秒，成功或恢复前台重置。后台暂停，前台恢复先回查，终态停止。切换节目/退出登录会取消旧请求并丢弃迟到结果，不能让旧响应覆盖新页面。

模型失败按`POST /jobs/{id}/retry`恢复，渲染失败按版本render接口恢复；`COST_UNKNOWN`不允许前端清除占用或强行重试。重启可能返回INTERRUPTED失败，由用户决定重试，不承诺自动继续。非幂等新建节目/版本/选方向请求结果未知时先查服务端，禁止盲目自动重放。

未保存编辑与持久任务分开：当前没有服务端编辑自动保存，需明确“尚未保存”，导航离开前提示；刷新会恢复已保存版本，不声称恢复所有输入。轮询不覆盖脏表单，409保留用户修改供核对。

2. 复用`POST /episodes`创建一期，取得ID后通过既有单文件multipart接口逐个上传，再进入该期既有四步。按钮立即防重复，保留已创建的ID与逐文件实际结果；上传完成仍须等待服务端格式、解码和额度校验。
3. 显示MP4/MOV、每期8段/600秒/1GiB限额；文件选择阶段允许移除尚未上传附件，不将图片、音频或第三方URL伪装为已支持格式。真实类型与总时长由后端判断。
4. 创建和发起人上传目前无幂等键。超时或断网造成结果未知时先回查，不自动重建或重传；已知节目ID继续在该期恢复，未知ID由用户核对列表。部分上传失败保留成功素材、想法及尚未完成的选择，给出继续处理入口。
5. “开拍”只创建节目与上传素材，不自动调用模型、确认证据、生成旁白、渲染或确认导出。背景想法是用户提供的制作意图，不作为已核实的视频证据。

“保存为新版”“确认此版本”“导出该版”仍按当前状态出现。简约化删除重复标语和次要说明，保留相关动作旁的上传限额、模式、费用/外发范围、授权影响和错误恢复说明。
