## 1. 阶段目标与范围

打通“发起人创建受限邀请→参与者供材或回答采访→本人预览并确认表达→发起人决定采用→形成新编辑版本→提出异议或撤回→依赖内容受限”的本机链路。未回复或跳过采访不阻断既有作品；新增供材和采访不会自动替换当前编辑版本。

| PRD范围 | 本阶段验收重点 |
| --- | --- |
| FR01多人供材、FR06；AC02、14–16 | 仅开放被邀任务及必要上下文，分别提交语音和补录视频，可预览、放弃或跳过；入口到期有明确状态 |
| FR07；AC05、17–19 | 本人表达确认与发起人采用分开；表达修订需要重新核对；不同人的记忆分别归属，不自动裁判事实 |
| FR08；AC13、20–22 | 有异议与未回复分别处理；受影响内容先限制使用，提出者确认解决或移除；不承诺删除外部下载副本 |
| FR09、10、12、13适用扩展；AC27、31–33 | 任务、确认及版本依赖持久化；渲染与导出前重验；撤回不被旧版本回退绕过 |

阶段2-3的固定版本受控分享、公开链接关闭/过期，以及阶段3的正式手机和电脑网页仍按既定路线后续实施。本阶段用不同浏览器会话验证不同身份，不将本机地址当作可外网发给朋友的正式服务。

## 2. 技术适配与运行边界

沿用Python3.12、FastAPI/Pydantic、SQLAlchemy/Alembic、SQLite、本地媒体目录、FFmpeg和单worker持久任务。业务权限与状态判断在后端，临时HTML只提供验收操作；不引入新的云资源、队列框架或模型依赖。

正常入口仍为 `scripts/run.sh`，绑定127.0.0.1:8788，云默认关闭。独立 `scripts/run-demo.sh` 为127.0.0.1:8790，数据在 `data/demo/`，固定结果和提示音继续醒目标明“非真实AI／非真实旁白”。已有正常数据不因本阶段开发而重建、覆盖或删除。

本阶段人工设置采访问题和表达建议，明确显示作者与核对状态；不把模板、人工文案或固定演示结果标成AI生成。后续真实模型建议仍须本人确认、预算许可和外发准入，不能借协作接口绕过三个云开关或3元/任务、30元/首批限制。

## 3. 身份、邀请与权限

- 发起人使用既有owner会话；参与者使用独立Cookie和CSRF令牌，只获得该邀请任务的权限。两种会话可以存在于同一浏览器，但不能互相代替。
- 邀请角色为contribute（供材）、interview（采访）和review（核对）。采访、核对需指定不超过30秒的上下文；问题最多8个，每个最多200字。供材／采访角色可改写或跳过本人收到的问题；review角色的问题和核对说明只读，仅能查看授权片段、提出异议及确认自己的异议解决，不能修改问题或新增投稿。
- 邀请默认有效7天。邀请明码只在创建时返回一次，数据库保存摘要；列表与日志不再返回明码。发起人可关闭邀请，后端每次访问检查当前状态。关闭或到期后不能新增投稿；已认领参与者仍能登录管理已有内容、提出异议和撤回，不能把失效邀请变成剥夺本人权益的手段。
- 参与者显示名及持码身份仅表示当前任务的角色归属，**不等于实名核验或已确认出镜者本人**。测试仍限本人或已获授权的成年人素材；发起人人工核对参与者和出镜者授权。
- 只展示必要问题及选定的上下文预览，不开放整期原片库、其他人的采访、owner列表或媒体路径。来源ID本身不授予访问权，伪造ID、跨邀请和跨节目均须拒绝。
- 未回复、跳过、邀请失效、上传失败、撤回和异议分别记录，不能将“没有回复”写成已同意采用或公开。

## 4. 媒体与容量约束

供材视频支持MP4/MOV；语音采访支持WAV/MP3/M4A，视频采访支持MP4/MOV。检查实际容器、音视频轨道、可解码性和资源上限，不只相信扩展名或浏览器MIME。

每条采访试验上限为60秒、100MB（100,000,000字节）。普通供材可单条超过60秒或100MB，沿用单期所有原始来源共用的8份、600秒、1GiB（1,073,741,824字节）上限；采访也计入该共享额度。待提交草稿、待采用供材及撤回授权后仍留存的文件都占配额，实际删除应用副本成功才释放，防止通过多名参与者、放弃或反复上传绕过限制。同一原始来源产生的预览或合成副本不重复计为新的原片。最终成片仍不超过90秒，沿用720p与原声保留规则。

所有输入只落应用生成的受控UUID路径，不改源文件。媒体命令使用参数数组、禁shell、网络协议白名单、超时和线程上限。上下文仅生成必要片段，参与者不能通过Range或改URL读取上下文之外的整段原片。采访必须标明为事后采访，不能拼接成现场发生的发言或反应。

采用后的语音采访使用本人原声与720p“事后采访”文字卡；视频采访保留本人画面和原声，并持续显示事后采访身份标记。本人确认的文字说明最多100字，存在时烧入视频；这是人工确认表达，不是自动语音识别结果。采用后生成独立素材，接入既有编辑器实际渲染，原版本保留。已采用供材和采访的确认修订均固定文字与区间；编辑器可排序或移除，另行裁短或改变字幕需新建表达修订并由本人重新确认，不能随意改写已确认表达。普通供材不烧入“事后采访”标签。文字投稿可记录和核对，本轮不把纯文字自动合成为本人声音。

## 5. 数据、确认与版本状态

新增的邀请、参与者会话、供材/采访草稿、表达修订、本人确认、发起人采用与异议记录保存到SQLite，包含节目、邀请、owner和participant归属。媒体文件单独保存，元数据保存原始来源、内容类型、时长、大小、受限状态及派生产物关联。采用Alembic增量迁移，保留阶段2-1既有表和数据。

状态约束以服务端转换为准：

1. 上传先进入本人可预览的草稿；提交和表达确认是明确动作。放弃草稿不会默认采用，也不因此向发起人公开。发起人只可查看曾由本人提交的内容及其后续撤回状态，不能凭withdrawn状态查看从未提交的草稿。
2. 发起人查看已提交内容，可提出人工表达建议。内容改变形成新修订，旧确认不自动授权新表达。
3. 本人确认具体修订后，发起人仍需单独决定采用；采用任务生成独立素材，由发起人显式加入编辑器并另存新版本，保留旧版，不原地替换已确认成片。确认或拒绝均为该修订的固定决定；改变表达需新建修订，不覆盖历史确认。
4. 未解决异议或撤回立即使相关来源与依赖版本受限；重新确认、渲染和导出时均检查当前依赖，旧文件存在不代表可以继续使用。
5. 异议由提出者确认解决，或通过移除关联内容处理；发起人不能直接替别人认可表达。无关且安全的版本可以继续操作。
6. 数据、人工确认和待处理任务必须跨服务重启保留；删除先限制访问，随后仅清理已登记的应用副本，失败可重试，不删除外部原片。

数据库迁移003新增Invitation、Participant、ParticipantSession、Submission、ExpressionRevision、Adoption、Objection七类协作实体。标识和归属为字符串，时间戳/时长为数值，上下文和问题为JSON；会话保存令牌摘要。提交以participant_id与client_request_id唯一约束防止重试重复，采用以revision_id唯一约束防止重复生成。

当前状态值：投稿uploading→draft→submitted，或failed/withdrawn；表达proposed→confirmed/rejected，撤回后withdrawn；采用pending→ready，或failed/revoked；异议open→resolved。采用失败通过error返回受控原因，重新检查权限与确认后才可重试。采访和供材撤回后立即停止使用，但按本机保留决定保存文件且仍占配额；撤回、关闭邀请与物理删除是不同操作。本人未提交草稿的显式删除正在接入联调：仅无表达修订且状态为draft/failed/withdrawn的本人稿件可删，删除失败保留待清理状态和配额，成功才释放。上述状态和约束需完成最终联调验收，新增删除接口尚未记录为测试通过。

## 7. API与错误契约

统一前缀 `/api/v1`。写操作验证当前角色、Cookie、来源和CSRF；错误结构沿用 `{"error":{"code":"…","message":"…"}}`，不返回堆栈、邀请码、会话值或原始供应商内容。长耗时媒体操作采用“提交任务→轮询任务→读取已登记产物”，不伪造进度。

已冻结的邀请与恢复接口契约：

| 方法与路径 | 请求与响应要点 |
| --- | --- |
| POST `/episodes/{id}/collaboration/invitations` | owner提交role、label、context、questions；创建响应含id、角色、有效期、上下文状态及一次性invite_code |
| GET `/episodes/{id}/collaboration/invitations` | owner读取 `{items:[…]}`，不再包含邀请明码 |
| POST `/participant/auth/login` | `{invite_code,display_name}`；返回participant_id、invite_id、display_name、csrf_token并建立独立Cookie |
| GET `/participant/auth/me` | 用已有参与者会话读取身份，不以重新登录代替恢复验证 |
| GET `/participant/invitation` | 读取本邀请的id、role、label、expires_at（Unix秒）、closed、accepting_new（是否仍接受新增内容）、问题及必要上下文；不能返回全量素材库 |
| POST `/collaboration/invitations/{id}/close`；POST同路径`/retry` | owner关闭新增入口，或重试失败上下文任务；关闭返回确认，重试返回Job |
| POST `/participant/auth/logout` | 参与者CSRF验证后结束当前参与者会话，不退出owner身份 |
| PUT `/participant/invitation/questions` | `{questions:[{id,text,skipped}]}`，供材／采访角色只能修改或跳过本人已收到的问题，返回邀请；review角色只读，写请求返回403 |
| GET `/participant/context/media` | 仅返回经过授权的必要片段，不返回原片全长 |
| GET `/participant/submissions`；GET `/episodes/{id}/collaboration/submissions` | 返回`{items:[Submission]}`；owner仅见曾提交过的内容及其撤回状态，不能偷看未提交草稿或从未提交便放弃的稿件 |
| POST `/participant/submissions` | `{text,question_id,client_request_id}`，创建文字草稿；请求编号须UUID，同编号不同内容返回冲突 |
| POST `/participant/submissions/upload` | multipart：file、kind、client_request_id、text及可选question_id；返回投稿及预览任务状态 |
| PUT `/participant/submissions/{id}` | `{text,question_id}`，仅本人草稿可改，返回投稿 |
| POST `/participant/submissions/{id}/retry` | 重试本人草稿的失败预览，返回Job |
| GET `/participant/submissions/{id}/media`；GET `/collaboration/submissions/{id}/media` | 本人可预览自己的草稿；owner仅预览已提交且仍可用内容 |
| POST `/participant/submissions/{id}/submit`；POST同路径`/withdraw` | `{confirmed:true}`，明确提交或撤回；返回更新后的投稿 |
| DELETE `/participant/submissions/{id}?confirm=true` | 本人显式删除未提交草稿；仅无表达修订且状态为draft/failed/withdrawn时允许。删除应用副本成功才释放配额；清理失败503，可重试。本接口的权限、物理清理失败重试与页面删除已验证；用户验收待进行 |
| POST `/collaboration/submissions/{id}/revisions` | owner提交`{text,start,end}`建立独立人工表达修订；不能越出原始投稿时间 |
| POST `/participant/revisions/{id}/decision` | `{decision:'confirmed'或'rejected'}`，仅该表达的参与者可决定，返回修订 |
| POST `/collaboration/revisions/{id}/adopt` | owner采用本人已确认的修订，返回持久Job；成功结果包含独立asset_id |
| GET `/participant/objections`；GET `/episodes/{id}/collaboration/objections` | 按身份返回`{items:[Objection]}` |
| POST `/participant/objections` | `{submission_id?,start?,end?,reason}`，只能指向本人投稿或本邀请授权上下文，返回异议 |
| POST `/participant/objections/{id}/resolve` | `{confirmed:true}`，仅异议提出者确认解决，返回异议 |

Submission响应含id、invite_id、participant_id、display_name、kind/state、text、question_id、filename、duration/size、preview_state/job_id/error、media_url及revisions/adoptions；本轮删除契约增加can_delete_draft、deleted、deletion_pending，分别表示是否可删草稿、是否已删除及是否仍待物理清理。ExpressionRevision包含id、submission_id、text、start/end、state、created_at；Adoption摘要含id、revision_id、state、asset_id、job_id及失败时的error。Objection包含归属及来源ID、区间、reason、state、created_at/resolved_at。任务沿用id、kind、state、stage、error、version_id和result契约，不返回物理路径。新增删除字段和失败重试路径仍须本轮最终自检验证。

主要错误：未登录401；CSRF、角色或上下文越权403；无权对象404；邀请关闭、未确认采用、修订冲突、内容受限或媒体未就绪409；容量超限413；格式、时间区间和请求编号无效422。错误code分别使用PARTICIPANT_AUTH_REQUIRED、CSRF_FAILED、ROLE_FORBIDDEN、CONTEXT_SCOPE、NOT_FOUND、INVITATION_CLOSED、CONSENT_REQUIRED、IMMUTABLE_CONFIRMATION、COLLAB_RESTRICTED、PREVIEW_NOT_READY、UPLOAD_TOO_LARGE等受控值，不能通过静默忽略继续生成。

## 8. 临时验收界面

在工作台选择节目，点击“朋友供材与采访”进入发起人协作页，创建供材、采访或核对任务，人工设置问题及必要上下文，查看提交与核对状态，再决定采用。参与者入口使用邀请登录，只显示该任务、本人预览与确认、异议及撤回操作；review角色的问题只读。网页必须提示持码角色与真实身份的区别，并将人工建议、事后采访和未确认表达明确区分。同一电脑新标签可快速体验双方流程；正式核对不同角色及不同参与者的权限时使用独立浏览器会话，不能把共享Cookie的新标签当成身份隔离证据。

临时页面位于后端静态目录，阶段3整体替换，不视为正式前端交付；是否表第4、7项按既有临时界面规则处理。新建邀请链接使用 `/participant#code=…` 的URL片段，仅用于启动时带入邀请代码；浏览器不将片段随初始HTTP请求发送。前端读取后立即用history.replaceState清除地址栏片段，不把明码写入请求URL、日志或localStorage等浏览器持久存储。用户确认登录时，代码仅通过同源POST请求体兑换受限HttpOnly Cookie会话，登录成功后清空输入框；会话值不放URL。邀请代码及含码链接不得进入截图和日志。创建时的明码仅供用户自行分发，本轮不代用户发送消息；当前链接仅适用于同一电脑的本机服务。

## 9. 测试与恢复要求
