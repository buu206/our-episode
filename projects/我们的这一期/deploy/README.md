# 在场：完整制作服务部署

此目录运行真实 Next.js + FastAPI + FFmpeg 服务，不是 GitHub Pages 静态演示。
代码已支持固定 HTTPS 域名、独立用户邀请、持久数据库和媒体目录。
当前交付为部署配置与本地检查；尚未在 Linux 服务器构建、运行或验收，不代表公网服务已经上线。

## 部署形态

单台 Linux 主机，Docker Compose，域名指向该主机，开放 80/443。
浏览器 → Caddy HTTPS → Next.js → 同容器内 127.0.0.1:8788 FastAPI → FFmpeg/模型接口。
只有 Caddy 对外开放端口。SQLite 与原片/成片存储在 `app_data` 持久卷；保持单实例、单 API worker，不做多副本扩容。
计算、磁盘和模型均可能产生费用，创建资源前由项目负责人确认。建议起点 4 核 / 8 GB，磁盘按素材量估算；这不是经过压测的容量承诺。

## 部署前需要配置

在服务器上进入产品目录，创建 `deploy/private/`（已排除 Git 和镜像构建上下文）。

1. `deploy/private/invites.json`：JSON 对象，键为 24–128 位随机邀请，值为不同用户的稳定归属 ID。每个用户独立一条；不能复用本机 `local-owner`，不能用演示通用邀请。
2. `deploy/private/app.env`：实际服务端模型配置。参考 `backend/.env.example` 与 `scripts/cloud_preflight.py` 的离线检查。不要直接复制本机试验授权或数据库。默认不开启云调用；供应商条款和本次用户素材范围确定后才启用对应能力。不能为了跳过检查把未核实的条件写成已核实。
3. 域名变量 `APP_HOST`：例如 `studio.example.com`，不是 GitHub Pages 地址。Caddy 会为该域名申请证书。
4. 文件仅允许服务器管理员与容器用户（UID 10001）读取。邀请文件需让容器用户可读，例如管理员配置组 10001、权限 640；目录 750。不要将密钥填入 Dockerfile 或公开文档。

在产品目录运行：

```sh
APP_HOST=studio.example.com docker compose -f deploy/compose.yaml up -d --build
```

该命令必须在已确认的主机上执行；当前尚未代执行。首次构建依赖、证书申请及域名解析需要网络。

## 上线验收（不能仅验证首页）

- 两个不同邀请登录，分别创建节目；验证互相不能读取素材、节目、成片和导出。
- 新建 → 上传真实 MP4/MOV → 模型分析 → 选方向 → 字幕/花字 → 音效/旁白 → 预览 → 确认 → 下载完整走一轮；保留请求费用记录。
- 检查 HTTPS 下 Cookie 的 Secure/HttpOnly、跨站写入拒绝、麦克风权限。
- 重启 app，节目、任务和人工确认仍在；处理中任务恢复；磁盘满/模型余额不足会清楚报错。
- 验证 30 天自动删除和主动删除；备份另设生命周期，不因恢复备份复活已删除素材。
- 配置备份、磁盘告警和服务监控。备份须涵盖一致的数据库与媒体文件；不要运行 `docker compose down -v`，它会删除卷。

## 已知范围

核心上传、人工编排和 FFmpeg 出片不依赖静态演示。真实 AI 能力仍取决于服务端模型、授权和预算配置；试验素材的限次授权不能作为所有新用户的通用授权。
部分自动人脸定位依赖独立 MediaPipe 环境及模型文件，镜像未自动下载这些资源；需单独配置并验证，不能承诺所有自动特效已在 Linux 可用。
邀请登录用于受控小范围使用；自助注册、支付、运营后台与大规模并发尚不在本轮交付范围。
